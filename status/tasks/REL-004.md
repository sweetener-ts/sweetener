## Published 2026-09-08

Tagged `v0.1.0-alpha.0` at `9db6289` and published nine packages from the
release workflow: `@sweetener/compiler`, `cli`, `unplugin`, `webpack-loader`,
`parcel-transformer`, `jest`, `prettier-plugin`, `node`, and `deno`. All nine
went out under the `alpha` dist-tag with public access, and npm signed a
provenance statement from the workflow's OIDC token for each.

The first attempt failed on the first package with `EOTP`, because the token
required an interactive one-time password. Nothing was published; the compiler
publishes first precisely so a credential failure lands before anything else
does. A granular token with Bypass 2FA enabled fixed it, and the same run was
re-run rather than re-tagged.

`latest` points at the alpha as well as `alpha`, which a first publish always
does: a package with no `latest` cannot be installed by name. The README says
so.

Verified after the fact by installing from the public registry into projects
created from scratch, with no local registry involved: Rsbuild builds and runs,
Bun runs `.sts` through the documented `bunfig.toml` preload, Farm builds and
runs, the Prettier plugin formats a `.sts` through the merged subpaths, and
`sweetener check` passes.
