# Sweetener 0.1.0-alpha.4

This alpha improves the reader and expansion paths used by ordinary TypeScript
as well as macro-enabled source. Package names, entry points, language version,
and format versions remain unchanged from alpha.3.

## Correctness

- Macro expansion now distinguishes names being declared from names being read
  across more declaration, type, arrow, and expression forms. A name held for
  TypeScript resolution is explained wherever it is actually unresolved.
- The reader uses TypeScript scanner evidence for tag boundaries and more of
  the type grammar for annotations. It accepts `module` and `namespace` as
  ordinary names, leading `|` and `&` in multiline annotations, and ambient
  and overload function signatures without bodies.
- Project `check` and `build` fail on errors, not warning-only diagnostics.
  Reader warnings remain visible but no longer turn otherwise valid projects
  into failed builds.
- A decimal integer spliced before a member access prints with a separating
  space: `1 .toFixed(2)` instead of invalid `1.toFixed(2)`.

## Tooling

- ESLint ignores local `.worktrees/`, matching the repository's Git ignore.

The remaining reader, diagnostic, expansion, benchmark, and test-reporting
follow-ups are tracked in [issues #6–#11](https://github.com/sweetener-ts/sweetener/issues).
