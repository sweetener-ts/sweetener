# Sweetener 0.1.0-alpha.3

Status: published.

A correctness release. Package names, entry points, and the integrations are
unchanged from [0.1.0-alpha.2](0.1.0-alpha.2.md). Several expansions that
compiled to TypeScript meaning something other than what was written now
expand correctly, and a few gaps in the language that pipe operators ran into
are closed.

## Expansion that meant the wrong thing

- An operator's operands kept their grouping only inside a function body: at
  the top level of a module, `$value * $n` over `1 + 2` and `3 + 4` printed
  `1 + 2 * 3 + 4`.
- A captured conditional or arrow lost its parentheses in a template:
  `twice(c ? 1 : 2)` with `$v * 2` printed `c ? 1 : 2 * 2`.
- An operator rule that matched only part of its operands was taken, and the
  rest dropped: with rules for `$v |> await` and `$v |> $f:expr`,
  `1 |> await g` expanded to `await 1`.
- `yield` was read at unary precedence, so `yield a + b` yielded `a`.
- An operator in a control statement's header -- `if`, `while`, `do`, `for`,
  `for...of`, `switch` -- and in an object literal's method was never
  expanded.
- `(1) |> f; const g = () => 1;` read `(1)` as the parameters of an arrow in
  the next statement.
- `p |> await |> f` overflowed the stack.
- A `yield` in a macro's argument was refused inside a generator, and a
  contextual keyword such as `from` or `of` was not an operand.

## Language

- **`#let(name = value) { body }`** evaluates a value once for a body that uses
  it. It becomes a function applied to the value; where the body holds an
  `await` or `yield` of its own, the value is assigned to a variable declared
  in the enclosing function instead, so both stay in the function they belong
  to, and each closure in the body keeps the value of its own evaluation.
- **`#parameterize(required % = ...)`** reports a body that never uses the
  parameter (`SWR4022`).
- **`refine $x form in (...)`** and **`form not in (...)`** over `conditional`,
  `arrow`, `assignment`, `yield` and `await`.
- **An operator rule may spell its right operand as literal tokens**, as
  `$value:expr |> await` does, and **`operand arrow;`** lets an infix
  operator's right operand be an unparenthesized arrow that ends at the next
  use of the operator.
- `SWR4023` reports an object literal that waits and has a method reading a
  `#let` variable, which cannot be given its own copy.

## Output

- Whitespace is kept wherever a token still follows the token it followed
  where it was written. Where an expansion joins tokens that were never
  written together, the gap is spaced as ordinary code:
  `total = reduce(map([1, 2, 3], (n) => n * 2), (sum, n) => sum + n, 0)`
  rather than `total =reduce(map( [1, 2, 3] ,(n) => n * 2) ,...)`.
- Parentheses an operand's own precedence makes redundant are left out, and an
  argument or array element is not parenthesized.

## Playground

- The pipeline example is now **Pipe Elixir**, where `x |> f(a)` calls
  `f(x, a)`, and **Pipe Hack**, TC39's pipe with `%`.
