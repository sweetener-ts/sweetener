# Sweetener 0.1.0-alpha.2

Status: published.

A language and compiler release. Package names, entry points, and the
integrations are unchanged from [0.1.0-alpha.1](0.1.0-alpha.1.md); what a
macro can say, and what the compiler reports when one goes wrong, has grown.

## Language

- **Syntax parameters.** `syntax parameter name:category` declares a name a
  template gives meaning to with `#parameterize(name = replacement) { body }`,
  after Racket's `syntax-parameterize`. A Hack-style pipe's `%` is one: every
  `%` the user writes in the body, including one a macro in the body produces,
  stands for the pipe's own binding, and a `%` between two operands is still
  remainder.
- **An `interface` or object-type member can be a macro.** A `typeMember`
  category, whose macros may expand to several members.
- **An ordinary binding shadows a macro**, as in Racket: a `const`, parameter,
  `catch` binder or `for`-`of` binding of a macro's name is that binding for
  its scope. Value and type stay apart.
- **`$$name`** writes and matches an identifier that begins with `$`, such as
  Drizzle's `$inferSelect`.
- **A `token` capture takes `>=` whole**, along with `>>`, `>>=`, `>>>` and
  `>>>=`, and a spelling refinement reads it whole.
- A macro generated inside a block is confined to that block.
- A syntax-class field may be named by a contextual keyword such as `unique`.

## Expansion

- A macro expands wherever it stands in a template: an argument, an operand,
  an arrow or function body, and a group after `,`, `?`, `:` or `=>`.
- A helper macro or operator a template uses expands whether or not the call
  site imports it, including in an operator's replacement.
- A macro no longer rewrites a property of the same name: `xs.map(f)` is left
  alone by a macro named `map`.
- `return 1 + ;` is no longer compiled to `return ;`.
- A type macro inside a `$x:type` capture is measured by its own rule, and a
  parameter list in a type is read as the head of a function type.
- A generic function type reads in a `.stsx` file.

## Diagnostics

- A macro no rule accepts is reported where the closest rule stopped, in the
  words of the innermost `expect` there, rather than at the macro's name.
- Reported rather than thrown or passed through silently: a macro that does
  not terminate (`SWR4014`, `SWR4015`), a definition written inside a block
  (`SWR4016`), a macro used above its definition (`SWR4017`), a syntax
  parameter used outside a parameterization (`SWR4018`, `SWR4019`), syntax
  that could not be read around a custom operator or in a template literal
  (`SWR4020`), and an operator left unexpanded (`SWR4021`).

## Command line

- `sweetener guide` prints the guide to writing macros. The package carries
  it, so `npx @sweetener/cli@alpha guide` works without installing anything.
- The README's `npx sweetener init` is `npx @sweetener/cli@alpha init`: the
  unscoped `sweetener` on npm is an unrelated package.
