# Sweetener 0.1.0-alpha.7

This alpha fixes one bug, reachable from the algebraic-datatype example that
ships with the playground. Package names, entry points, language version, and
format versions remain unchanged from alpha.6.

## Correctness

- A `data` declaration whose variants carry no fields can be declared and
  matched. `data Color = Red() | Green()` failed with
  `SWR6201: Project expansion failed: Binding contract selected no region
values`, and so did a match whose arms happen to bind nothing, such as
  `match (t) { Leaf() => 0; }` over a type with a field-carrying variant.

  A binding contract whose capture path selects nothing now binds nothing,
  rather than refusing. The refusals looked as though they caught a contract
  naming a capture the rule does not have, which is caught when the macro is
  compiled (`SWR3002`); what was left for them to catch was a repetition that
  matched nothing, which is ordinary. Because the refusal was thrown rather
  than reported, it reached the author as an expansion failure instead of a
  diagnostic about their source.

  Exhaustiveness checking is unchanged: a variant left unhandled is still
  reported, and now symmetrically -- it no longer depends on which variant you
  drop.

The remaining expansion, diagnostic, benchmark, and language follow-ups are
tracked in [the open issues](https://github.com/sweetener-ts/sweetener/issues).
