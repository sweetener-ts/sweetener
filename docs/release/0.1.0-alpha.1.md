# Sweetener 0.1.0-alpha.1

Status: published.

A documentation and release-plumbing release. The compiler, the language, and
every package's public surface are unchanged from
[0.1.0-alpha.0](0.1.0-alpha.0.md).

## What changed

- The project status records the alpha as published rather than as blocked on
  authorization.
- `docs/release/0.1.0-alpha.0.md` carries the per-package trusted-publisher
  configuration, which could not be written down before the names existed.
- The release workflow's own guidance about `registry-url` was wrong and is
  corrected: npm's CLI detects an OIDC environment and uses it before falling
  back to a token, so `setup-node` keeps `registry-url` when the token goes.
- `scripts/release-check.mjs` no longer pins the version it checks. It read
  `0.1.0-alpha.0` from a literal, and required a release note by that name, so
  cutting a second release meant editing the check meant to police it.

## Why it exists

To publish once over OIDC with no `NPM_TOKEN` present, and so establish that
the trusted publishers configured for all nine packages work. A dry run cannot
establish it: `npm publish --dry-run` does not authenticate, and one passed
against a token that could not publish.
